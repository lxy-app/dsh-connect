# DSH Connect Website 主页原型说明

- 原型文件：[../prototype/dsh-connect-website-prototype.html](../prototype/dsh-connect-website-prototype.html)
- 类型：独立、可交互的单文件 HTML 设计原型
- 状态：待设计评审；尚未进入真实 Website 工程实现
- 目标线上地址：`https://lxy.app/dsh-connect`
- 数据：页面中的设备、会话、审批与管理后台数据均为模拟值

## 1. 打开方式

直接使用浏览器打开 `prototype/dsh-connect-website-prototype.html`。

原型不依赖构建工具、Go Server、DeepSeek Harness 或互联网，HTML、CSS、JavaScript、SVG 图标与品牌 PNG 均包含在同一文件中。页面内的“体验交互原型”会打开同目录的 `prototype/dsh-connect-prototype.html`；GitHub 链接需要联网。

## 2. 设计方向

### 核心表达

主标题为“离开桌面，继续把想法做成。”，强调 DSH Connect 不是远程桌面，而是让用户离开电脑后仍能查看、推进和审批桌面 DSH 会话。

### 视觉语言

- 品牌标识统一使用 `apps/mobile/assets/images/icon.png`，覆盖导航、手机演示、收尾 CTA 和页尾；原图以 Data URI 内嵌，保持单文件离线打开，Web 展示只增加圆角裁切，不修改原 PNG。
- 沿用应用图标的紫色调与薄荷绿在线状态色。
- 首屏采用深色产品主视觉，搭配网格、连接轨道、手机模型和浮动状态卡。
- 功能区使用明亮的 Bento 卡片，管理后台展示卡重新切回深色，形成节奏变化。
- 安全区使用深色背景，突出架构链路与安全边界。
- 支持浅色/深色页面主题；首屏与安全区保持固定深色，以维持品牌视觉一致性。

### 内容结构

1. 固定导航与首屏产品价值表达。
2. 四项事实条：实时流式回复、工作区级授权、一次性远程审批、自托管部署。
3. 产品能力 Bento 区：会话进展、远程审批、分权控制、团队治理。
4. 三步工作方式：接入桌面、明确授权、移动推进。
5. 安全设计与连接架构。
6. 五项常见问题。
7. 产品原型与 GitHub 行动入口、目标线上地址及许可证信息。

## 3. 可评审交互

### 首屏模拟会话

- 点击指令建议可填入输入框。
- 点击发送或按 Enter 后，依次展示用户消息、等待状态与模拟 Assistant 回复。
- 空指令会显示提示，不产生消息。
- 发送期间暂时锁定输入，模拟回复完成后恢复。
- “重置演示”恢复初始会话。
- 所有内容只写入当前页面内存，不连接真实 DSH。

### 远程审批

- 首屏浮动审批卡可跳转到功能区审批卡。
- “允许一次”和“拒绝”分别展示不同结果状态。
- 处理后可通过“重置”恢复待审批状态。
- 该交互不会执行命令，也不会改变真实审批。

### 工作区动作授权

- “查看会话、发送指令、取消执行、远程审批”可分别切换。
- 底部摘要实时显示已授权动作数量，包括全部撤销后的零授权状态。
- 该交互仅用于表达分权模型，不保存或下发授权。

### 工作方式与 FAQ

- 三步工作方式可点击切换，右侧同步更新连接链路与说明。
- FAQ 每项可独立展开或收起。

### 导航与主题

- 导航锚点连接各内容区，滚动时更新导航状态。
- 小屏幕提供移动菜单，选择后自动关闭，Escape 也可关闭。
- 主题按钮切换浅色/深色页面变量。
- 适配 `prefers-reduced-motion`，减少动态效果时内容直接可见。

## 4. 内容事实边界

原型文案基于仓库现有产品、架构和实现说明，只表达已有或明确支持的架构能力：

- 会话历史、实时流式回复、提示词、取消与远程审批。
- 手机配对与桌面授权分离，按工作区和动作分权。
- Connector 主动出站连接，桌面无需公网入站端口。
- DSH Session Log 为会话事实源。
- requestId 幂等、事件恢复和一次性失败关闭审批。
- Web Admin 用户、设备、权限与审计治理。
- Apache License 2.0 与自托管部署。

没有加入虚构下载量、用户数量、客户评价、价格、应用商店下载或尚未实现的推送承诺。界面中的指标仅作为管理后台视觉演示，并标注“演示数据”。

## 5. 响应式与可访问性设计

- 桌面首屏采用左右双栏；窄屏改为居中文字与下方手机模型。
- Bento 卡片在平板和手机下逐步改为单列。
- 安全架构在手机上由横向链路改为纵向节点。
- 覆盖 1440px、390px 和 320px 视口，无页面横向溢出。
- 提供键盘焦点、跳过导航链接、语义化按钮、ARIA 展开/选中状态和动态结果播报。
- 装饰性产品模型使用较小字号以维持比例；正文与真实操作控件不沿用模型内部的缩放字号。

## 7. 评审确认点

建议重点确认：

1. 首屏主标题与“不是远程桌面”的产品表达是否准确。
2. 深色首屏 + 明亮 Bento 功能区的视觉方向是否符合品牌预期。
3. 手机会话、远程审批与分权授权是否作为首屏和首组核心展示。
4. 三步工作方式与安全架构的信息深度是否合适。
5. 主行动入口是否继续指向现有完整产品原型，或改为真实控制台/安装指引。

待原型设计确认后，再确定真实 Website 的技术栈、组件拆分、线上路径与管理后台入口关系，并进入正式工程实现。
