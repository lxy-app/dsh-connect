# DSH Connect 实施路线与验收设计

- 文档状态：实施建议
- 版本：v1.0
- 日期：2026-10-27

## 1. 实施原则

1. 先验证真实 DSH 集成，再扩展移动 UI。
2. 先做会话控制闭环，再开放远程审批、附件和终端。
3. 每个阶段都必须验证桌面启动、升级、回退和真实运行，不以语法检查代替运行验证。
4. 所有高风险能力默认关闭，按设备和工作区逐步开放。
5. 原型只用于设计评审，不作为真实 Connector 的安装基础。

## 2. 阶段划分

## P0：真实技术验证

### 目标

打通单桌面、单会话、单客户端的真实链路，验证 DSH Host API 和网络协议可行。

### 范围

- 最小 Connector，仅包含必要 Host 能力。
- Connector 与单实例 Go Server 建立 WSS。
- `session.list/page/prompt/follow/cancel`。
- 简单命令与事件协议。
- 桌面配对码最小流程。
- 使用调试客户端验证，不追求完整 App 视觉。

### 必做验证

- DSH 安装、启动、停用、重启和卸载均正常。
- Connector 加载失败不会破坏整个 DSH 启动。
- DSH 重启后可重新列出并恢复会话。
- 服务端断线可重连。
- 真实流式输出和取消行为正确。

### 通过门槛

真实链路成功，且故障回退经过验证后，才进入完整 MVP。

## P1：单用户、单桌面 MVP

### App

- Server 连接和手机配对。
- 桌面在线状态。
- 会话列表、搜索、详情和历史分页。
- 流式输出。
- 排队发送提示词。
- 取消当前 Turn。
- 完成/失败通知。
- 断线重连与消息补拉。
- 生物识别。

### Connector

- 正式配对和桌面授权。
- 工作区白名单。
- 命令幂等和请求超时。
- follow 订阅管理。
- 版本能力与错误码。
- 设置、授权和诊断页面。

### Go Server

- 用户、设备、配对和令牌。
- 单实例 Device Hub。
- REST + WSS。
- 幂等记录、基础审计和推送。
- TLS 与离线快速失败。

### 管理后台

- Owner/Admin/Member 基础角色。
- 用户与设备管理。
- 桌面/工作区基础授权。
- 在线状态与运行会话元数据。
- 基础审计、配对和通知配置。

## P2：安全与团队能力

- 待办中心与远程审批。
- 多桌面、多手机和多工作区。
- 细粒度权限和 Auditor。
- 审批策略、二次认证和审批审计。
- Connector 版本兼容管理。
- 高级通知和锁屏隐私。
- 会话正文敏感权限及审计。
- 管理员异常任务处理。

## P3：效率与规模化

- 图片和附件。
- 模型与 Agent Preset 选择。
- 消息搜索和常用指令模板。

- Redis/NATS、多实例 Server。

## 4. 核心验收标准

### 4.1 桌面插件生命周期

- 安装后 DSH 可正常启动。
- 启用、禁用、热更新和卸载行为明确。
- Connector 异常被隔离，不能导致整个 Harness 不可用。
- 移除后无残留加载项。
- 版本不兼容时给出可理解的错误和回退路径。

### 4.2 配对与授权

- 配对码只能使用一次，过期后不可用。
- 桌面显示并核对 Server 和设备指纹。
- 未确认授权前，Server 不得读取会话。
- 仅授权工作区可被远程访问。
- 取消授权不会删除 DSH 本地会话。
- 手机配对不隐式获得桌面权限。

### 4.3 会话控制

- App 可查看真实会话和历史。
- 发送后明确区分 accepted 和 completed。
- 流式事件顺序正确，持久事件不丢失。
- queue/steer 行为与 DSH 一致。
- 取消只影响目标会话的当前 Turn。

### 4.4 幂等与恢复

- 同一 requestId 重试不产生重复提示词。
- App 杀进程重开后不重复发送。
- Server 重启不导致重复执行。
- 按游标恢复持久事件。
- 游标失效时可通过 snapshot/page 对齐。
- 离线不会自动执行陈旧草稿。

### 4.5 远程审批

当前状态：首版已实现（`approval/request` + `user-questions/request`，手机轮询 + 一次性决定，桌面链并行保留；生物识别与推送深链待补）。

- 高风险操作必须展示足够上下文。
- 允许一次不能变成永久授权。
- 超时、离线和协议错误不得批准。
- 多端同时响应只有一个有效决定。
- Connector 不处理时保留桌面审批链。
- 所有审批有完整审计。

### 4.6 权限与吊销

- 用户只能看到授权桌面和工作区。
- 吊销手机后新命令立即失败。
- 吊销 Connector 后新控制连接立即失败。
- 管理后台默认不能浏览所有会话正文。
- 权限变更有前后差异审计。

### 4.7 移动后台与通知

- 后台不依赖永久 WSS。
- 完成、失败和审批可通过 APNs/FCM 通知。
- 通知点击深链到正确页面。
- 锁屏默认隐藏正文。
- 回前台后状态与 DSH 对齐。

## 5. 测试策略

| 层级 | 重点 |
|---|---|
| Protocol contract | Go/TS Schema、版本、错误码、兼容性 |
| Connector unit | DTO 映射、幂等、游标、授权、超时 |
| Connector integration | 真实 DSH 启动、会话、取消、审批和重启 |
| Server integration | 配对、Token、路由、吊销、重连和推送 |
| App E2E | 配对、发送、恢复、审批、后台通知 |
| Admin E2E | 用户、设备、策略、审计和敏感权限 |
| Failure injection | 断网、重复包、乱序、慢客户端、Server/DSH 重启 |
| Security | 越权、重放、配对码复用、Token 吊销、payload 限制 |
| Upgrade/rollback | DSH/Connector/协议升级与卸载回退 |

## 6. 主要风险与缓解

| 风险 | 缓解 |
|---|---|
| DSH API 升级破坏 Connector | 适配层集中、能力协商、契约测试、最低兼容版本 |
| 插件异常影响 DSH 启动 | 最小 Host 入口、故障隔离、分阶段验证、可靠卸载 |
| 远程提示词造成高权限执行 | 工作区授权、审批保留、限权、审计、默认不开放 Shell |
| 断线重复执行 | requestId 全链路易幂等、恢复后先核对状态 |
| 事件丢失或乱序 | 持久 seq、快照恢复、背压、临时流与持久事件分离 |
| 移动后台无法实时接收 | APNs/FCM + 前台补拉，不承诺永久连接 |
| Server 可见敏感内容 | 私有部署、最少存储；必要时端到端加密 |
| 多端审批冲突 | 单次消费、有效期、明确显示其他端处理结果 |

## 7. 发布门槛

每个版本发布前必须确认：

1. 安装、启动、升级和卸载全部通过。
2. 权限、审批和吊销安全约束无回归。
3. 断线、重启和重复请求测试通过。
4. 协议兼容和错误提示可理解。
5. 文档、迁移指南和回退方案同步更新。
6. 不用“安装成功”或“语法通过”替代真实功能验收。
