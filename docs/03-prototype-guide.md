# DSH Connect 高保真原型说明

- 原型文件：[../prototype/dsh-connect-prototype.html](../prototype/dsh-connect-prototype.html)
- 类型：独立、可交互 HTML
- 状态：用于产品评审与交互演示
- 数据：全部为模拟数据

## 1. 打开方式

在 macOS 上双击文件，或在文件管理器中选择默认浏览器打开。

不需要：

- 安装 DSH 插件。
- 启动 Go Server 或 Web Server。
- 安装 React、React Native 或 Node 依赖。
- 连接 DeepSeek Harness。
- 访问互联网。

原型可以离线运行，所有 HTML、CSS 和 JavaScript 均在同一个文件中。

## 2. 原型与真实产品的边界

### 原型包含

- 移动 App 高保真页面。
- 桌面 Connector 接入与授权流程。
- Web 管理后台页面。
- 前端状态切换和模拟反馈。
- 明暗主题与响应式布局。

### 原型不包含

- 真实 DSH Host API 调用。
- 真实 Go Server、认证、WSS 或数据库。
- 真实 React Native 工程。
- 真实会话、工具执行或审批。
- 真实二维码配对、推送或设备吊销。

原型中 `MacBook Pro`、`Liwei MacBook`、`Connector 1.0.0`、会话消息和审批记录均为演示内容。

## 3. 顶部三套视图

```text
移动 App｜桌面 Connector｜管理后台
```

这三套视图对应真实产品的三个不同使用端：

- App：移动控制。
- Connector：将已有 DSH 桌面绑定为受控设备。
- Admin：组织、设备和权限治理。

## 4. 推荐演示路径：完整接入 DSH 桌面

### 第一步：生成桌面配对码

进入：

```text
管理后台 → 设备管理 → 添加桌面
```

页面展示：

- 一次性配对码 `DC-8F2K-91PQ`。
- 示意二维码。
- Server 地址。
- 有效期。
- “生成配对码 → 桌面建立连接 → 授权并上线”步骤条。

### 第二步：打开桌面 Connector

点击“打开桌面 Connector”。

未连接页面展示：

- Server 地址。
- 配对码输入框。
- 主动 WSS 连接说明。
- Connector 与 DSH Host API、Go Server、App 的关系。

也可以直接通过顶部“桌面 Connector”进入，并点击“使用演示配对码”。

### 第三步：连接 Server

点击“连接 Server”。

原型进入待授权状态，模拟 Server 已完成配对码校验。

### 第四步：桌面确认开放工作区

核对：

- Server。
- 桌面名称。
- 设备指纹 `8F:42:9C:71:DC`。
- 工作区选择。
- 远程执行风险提示。

点击“确认授权并上线”。这里选择的是桌面允许开放的工作区，不等于已授权某台手机访问。

### 第五步：查看三端联动

- Connector 显示在线、心跳、工作区和接入记录。
- 点击“在管理后台查看”，后台显示接入成功。
- 后台设备列表新增 `Liwei MacBook`。
- 切换到移动 App → 设备；此时还看不到新桌面，因为当前用户的访问策略尚未包含它。
- App 的“添加另一台 DSH 桌面”卡片可重新进入接入流程。

### 第六步：关联用户、桌面与工作区

1. 进入“管理后台 → 访问策略”，在“关联用户”中确认李伟和陈晨已关联“移动端研发组”。
2. 在“授权桌面”中勾选 `Liwei MacBook`，保留其他已选桌面。
3. 在“授权工作区”中勾选策略允许的范围并保存。
4. 也可以从“用户与角色”进入某用户的“关联策略”，再通过“手机预览”检查该用户实际可见的设备。

### 第七步：手机申请访问这台桌面

1. 在 App 的 `Liwei MacBook` 卡片点击“申请手机访问”。
2. 核对工作区、动作和手机身份；页面明确显示 `mob_demo_01` 保持不变，无需重新扫码。
3. 提交访问申请，再点击“前往桌面确认”。
4. 在 Connector 的“确认手机访问申请”卡片中点击“确认手机访问”。
5. 返回手机后，新桌面显示“已授权”，可用于新建会话；原有桌面的授权保持不变。

这套流程用于评审“一次手机配对、多台 DSH 桌面逐台授权”，不是多 Server 连接方案。

## 5. 移动 App 页面与交互

### 5.1 会话

- 搜索会话。
- 全部、运行中、待处理、已完成筛选。
- 点击会话卡片进入聊天。
- 新建会话：点击聊天页右上角 `+`，或打开左侧抽屉点击“新建会话”；工作区旁的 `+` 会预选对应工作区。
- 新建会话默认沿用当前设备和工作区，可填写首条指令并查看字数；切换设备或工作区时保留草稿。
- 离线设备展示原因并禁用创建；空指令显示行内校验。创建后进入新会话，首条指令和模拟回复会保留，新会话也会出现在抽屉中。

### 5.2 会话详情

- 查看用户、Assistant 和工具调用卡片。
- 输入补充指令并发送。
- 模拟 DSH 接受指令和 Assistant 回复。
- 返回会话列表。

### 5.3 待办与审批

- 打开“运行集成测试”审批。
- 查看命令、工作区、设备、发起者和有效期。
- 拒绝后返回待办。
- 允许一次需要经过 Face ID 模拟确认。
- 处理后待办状态清空。

### 5.4 设备

- 默认展示 `MacBook Pro` 与 `Office Mac Studio` 两台已授权桌面，可分别打开对应会话。
- 每台桌面独立展示在线状态、手机访问授权、工作区数量和活跃会话数。
- 设备列表按当前用户的访问策略过滤；未关联策略或未包含桌面的用户不会看到其他设备。
- 新桌面必须先加入用户策略，再经过“手机申请 → 桌面确认”才会进入可控制列表。
- 手机卡片始终使用同一个 `mobileDeviceId`，明确“仅配对一次”。
- “配对与重装恢复”入口可进入恢复演示。

### 5.5 我的

- 任务通知、审批通知、生物识别和锁屏隐私开关。
- Server、配对与重装恢复和诊断入口。
- 明暗主题由顶部主题按钮控制。

### 5.6 配对与重装恢复

入口：

```text
我的 → 配对与重装恢复
设备 → 配对的手机 → 配对与重装恢复
```

点击“模拟重新编译安装”后，原型依次表达：

1. 读取同一台 iPhone 的 Keychain 凭据。
2. 恢复原 `mobileDeviceId`，不创建新手机配对。
3. 恢复全部已授权桌面，授权数量和新增桌面状态不变。
4. 无需重新扫码，可直接返回设备页继续控制桌面。

该页面仅演示同机、同 Bundle ID 与签名身份的恢复设计，不模拟 Keychain 已丢失、换机或跨签名身份恢复。

## 6. 管理后台页面与交互

| 页面 | 演示内容 |
|---|---|
| 概览 | 指标、近 7 日趋势、实时会话、审批和最近动态 |
| 用户与角色 | 用户列表、角色、关联策略、手机可见桌面数与按用户预览 |
| 设备管理 | 桌面列表、添加桌面向导、配对状态、吊销入口 |
| 访问策略 | 桌面/工作区多选授权与查看、发送、取消、审批开关 |
| 运行与会话 | 运行元数据和状态 |
| 审批策略 | 待审批列表、远程审批与生物识别策略 |
| 审计日志 | 操作者、目标资源、结果和请求 ID |
| 系统设置 | Server、Token、通知、审计与运行环境 |

### 6.1 访问策略的多选配置

“关联用户”“授权桌面”和“授权工作区”均使用多选下拉控件：

- 点击选项可连续勾选或单独取消，不会用新选项覆盖已选项。
- 显示已选数量，支持全选、清空和“完成”关闭；`Escape` 也可关闭菜单。
- 三类选择互不影响，菜单下方汇总关联用户、桌面与工作区数量。
- 桌面或工作区为空时禁用“保存策略”；未关联用户的策略可以保存，但不会对任何手机生效。
- 修改已保存选择会重新标记为未保存状态。

这些交互只改变原型中的模拟策略，不修改真实 Admin 或 Server 授权。

### 6.2 用户关联与手机可见设备

原型提供双向入口：

- 用户与角色：查看每个用户的关联策略和手机可见桌面数，进入“关联策略”或“手机预览”。
- 访问策略：通过“关联用户”多选决定策略对哪些用户生效。

可见性规则：

```text
用户已关联策略
AND 桌面包含在策略中
→ Server 才应在手机设备列表中返回该桌面
```

未关联策略的用户看到“没有可见桌面”，不会看到其他桌面卡片。将用户或桌面移出策略后，对应设备立即从预览中消失；已有手机 grant 不绕过该可见性规则。策略预览只验证设备可见范围，实际控制仍需手机单独获得桌面 grant。

目标有效权限为：

```text
用户策略允许范围
∩ 手机 active grant
∩ 桌面开放的工作区与 scopes
```

### 6.3 真实工程现状与缺口

本轮代码核对发现，真实 Server 当前尚未实现上述策略过滤：

- `GET /v1/mobile/access` 读取全部桌面，仅排除吊销和待桌面授权状态。
- `POST /v1/mobile/access/requests` 校验桌面开放的工作区和 scopes，但未校验用户访问策略。
- 当前真实 Admin 也没有这套策略关联页面；本页交互仍是独立原型。

正式实现时必须由 Server 在设备列表、访问申请、会话、消息、审批和 WSS 等所有链路统一鉴权，不能只在手机 UI 隐藏设备。本轮未修改这些生产代码。

## 7. 视觉与交互规范

- 桌面管理后台采用侧边导航、指标卡、数据面板和表格。
- App 使用 390 pt 手机框架，模拟状态栏、底部导航和审批弹层。
- App 字体按可读性分层：聊天、输入和主要正文使用 16px，代码及普通说明使用 13–14px，功能性辅助信息不低于 12px；这些调整仅作用于手机原型，不影响 Connector 或管理后台。
- Connector 使用独立桌面窗口，避免与手机或管理后台混淆。
- 支持浅色/深色主题。
- 功能图标使用 inline SVG；顶部导航、管理后台和桌面 Connector 的 LOGO 全部使用当前应用 `icon.png`，共用同一份内嵌 data URI，无外部网络依赖。
- 主要按钮提供 Toast 或页面状态反馈。
- `Escape` 可关闭手机审批弹层。
- 小屏幕下隐藏辅助导览并允许内容滚动。

## 8. 演示时必须说明的限制

1. 二维码是示意图形，不可扫描。
2. 配对码、指纹和 Server 均为固定演示值。
3. “连接”“授权”“吊销”“发送”不执行真实操作。
4. 切换页面只改变浏览器内存状态，刷新后恢复初始演示数据。
5. 重装恢复只模拟界面状态，不读取真实 Keychain，也不执行 Xcode 编译或真机安装。
6. 原型不是实际 Connector，也不会随 DSH 启动。

## 10. 本轮待评审确认

1. “添加 DSH 桌面”和“手机配对/修复”是否按原型拆成两个独立入口。
2. 是否采用“桌面开放工作区”与“手机访问授权”两段确认，避免接入桌面即默认授权手机。
3. 是否确认重装恢复仅覆盖同机、同 Bundle ID 与签名身份；Keychain 丢失另行进入安全恢复流程。
4. 是否确认“用户策略决定可见与可申请范围，手机 grant 决定实际控制范围”的两层授权模型，并在正式实现时由 Server 全链路强制过滤。

评审确认后再进入真实工程实现，本轮不修改 Mobile、Server 或 Connector 生产代码。
